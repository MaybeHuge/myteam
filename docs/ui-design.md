# 界面设计基线

更新日期：2026-10-28。适用于工作台、项目空间、需求/任务/用例、质量流程及成员/账号管理。

## 1. 视觉方向

采用清晰、轻盈的研发协作界面：深色侧栏承载导航，浅色画布承载工作；青绿色强调操作，其他低饱和配色用于区分项目。

| 项目       | 当前约定                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 主色       | #26785e，用于主操作、当前导航和焦点                                    |
| 主画布     | #f5f7f2，白色卡片                                                      |
| 主文字     | #304538                                                                |
| 次级文字   | #65725f 为主要基线，避免以过浅颜色表达重要内容                         |
| 项目配色   | 青绿、蓝、紫、琥珀、玫瑰，配合图标与名称识别                           |
| 圆角       | 控件约 8 px、卡片约 12 px                                              |
| 间距       | 以 4/8 px 为基础，常用 12/16/20/24/32 px                               |
| 字号       | 标题约 26–31 px，正文约 12–14 px，辅助信息至少 11 px；窄屏标题适当缩小 |
| 边界与阴影 | 细边框和轻阴影，避免每个区块都使用强对比背景                           |

以上为实现基线，不代表已完成全平台无障碍合规认证。继续检查实际页面的文本可读性、焦点、加载和交互反馈。

## 2. 布局与组件

- 侧栏展示工作台、项目空间、账号管理及真实最近更新项目；权限不足时不提供管理入口。
- 顶栏提供当前位置、授权项目切换、项目快速搜索、站内通知、账号及退出。Ctrl/Command + K 聚焦搜索，中文输入法确认不触发误跳转。
- 工作台优先展示本人负责的迭代跟进，提供真实统计、截止日期、逾期提示与对象入口；项目概览和最近更新继续保留，不填充虚构任务数量。
- 项目空间提供范围、关键词和状态筛选，支持卡片/列表切换，筛选及分页写入 URL。
- 卡片包含项目图标、名称、简介、状态、日期和成员；状态同时提供文字与标记。
- 项目详情使用概览、迭代、需求、任务、用例、测试记录、版本构建、缺陷及协作/成员页签，提供真实动态和责任信息。
- 创建/编辑及角色配置使用抽屉，保留上下文；重要状态改变使用明确确认对话框。
- 成员角色使用可兼任的选择卡片，解释职责；主负责人保护在服务端再次执行。
- 表格过宽时在容器内滚动，不让整页横向溢出。

## 3. 状态与交互

- 等待数据时使用骨架；空数据、无筛选结果、无权限、网络错误分别处理。
- 保存期间阻止重复触发，成功后刷新相关数据并提供简短反馈。
- 服务端错误保留表单内容；409 不自动替换版本并覆盖，使用打开编辑器时的记录快照。
- 带图标的关键按钮提供明确可访问名称，加载图标不改变按钮含义。
- 键盘焦点必须可见；颜色选择和角色选择支持键盘操作。
- 卡片轻微上浮、边框和反馈使用短过渡；尊重 prefers-reduced-motion。
- 窄屏收起导航文字、统计调整为两列、项目卡片调整为单列。
- 页面中不混入框架、数据库、任务编号或未实现功能说明等开发细节。

## 4. 实现位置

- 应用主题与布局：apps/web/src/app/App.tsx、apps/web/src/styles/global.css。
- 项目组件与样式：apps/web/src/modules/projects/，通过 CSS Modules 管理。
- 公共展示：presentation.tsx 中的项目图标、状态和成员头像。
- 行为验证：tests/e2e/identity.spec.ts、tests/e2e/projects.spec.ts。
- 本地截图与功能证据：[本批验证记录](verification/m1-projects.md)。

后续新增页面先复用已有组件和状态模式，只有明确业务差异时扩展；不为美观增加没有实际行为的按钮、占位指标或虚构项目数据。

添加项目成员使用可搜索下拉框：默认展示可加入的已有账号，选项提供头像、姓名和邮箱；按姓名/邮箱远程检索，输入防抖 250 ms，分页支持滚动与“加载更多”按钮。已加入或已停用账号由服务端过滤；选择后保留完整身份信息，抽屉关闭后清空。保留加载、无匹配、无可用账号、失败重试与键盘选择状态。

迭代计划使用项目内页签、可点击状态统计、卡片列表与详情抽屉。卡片突出目标、日期、负责人和真实范围进展，未关联事项时不显示虚假完成率。详情展示未完成警示与关闭总结，编辑和状态确认保存打开时的版本；筛选、分页及选中详情保存在 URL。样式位于 apps/web/src/modules/iterations/iterations.module.css，窄屏卡片单列、统计两列、日期表单单列，保留只读与失败反馈。

协作区沿用白色卡片、低饱和青绿和清晰边界，讨论与附件按对象分开分页。评论纯文本保留换行并自动换行长内容；附件显示真实名称、大小、上传人与时间，窄屏将下载操作换行以保留文件名空间。上传失败有可重试提示，等待、空态及只读状态明确展示。

站内通知以顶部铃铛、真实未读数及抽屉承载，未读同时使用底色/圆点与「标为已读」操作区分，支持筛选、分页和对象跳转。通知不被当成当前业务待办。代码位于 apps/web/src/modules/collaboration/，验证见 [协作记录](verification/m1-collaboration.md)。

工作台跟进区使用四项可点击统计、关键词搜索、稳定分页及可直接进入的迭代记录。状态同时有文字与颜色，截止日当天不算逾期。搜索和页签保存在 URL，刷新保持，合法越界页提供「返回第一页」。已解决事项从当前列表移除，站内通知继续按历史消息展示。

项目切换支持搜索、滚动分页、加载更多、无匹配与失败重试；保留共同页签，清除旧对象和表单上下文。项目详情返回列表保留原搜索与视图；成员搜索和分页同样写入 URL。会话失效清理旧查询缓存，未知地址展示可返回的 404 页面。行为证据见 [应用框架验证](verification/m1-framework.md)。

## 需求管理（M2-01）

项目详情新增“需求管理”标签。列表显示项目内编号、标题、状态、优先级、负责人和迭代；支持关键词、状态、优先级、类型、负责人及迭代筛选和分页，URL 保留筛选及当前需求，刷新可恢复。只展示当前用户可以执行的创建、编辑及评审操作，服务端继续独立授权。

新建/编辑用抽屉，草稿只要求标题；送审时用独立对话框选择评审人。成员及迭代选择支持搜索和继续加载，评审人只显示本项目符合权限的可用成员。已纳入迭代的需求调整时提示填写原因。

详情展示需求正文、验收标准及责任信息，并分为“需求内容 / 评审历史 / 讨论与附件”。评审历史按轮次倒序，显示操作者、指定评审人、时间及意见，可展开当轮内容快照；确认后的只读状态有明确反馈。错误保留输入并允许重试，版本冲突要求刷新，通知可以直达需求详情。列表在窄屏内部横向滚动，页面保持视口宽度。

## 任务管理（M2-02）

项目详情新增“任务管理”；需求详情提供“查看关联任务”和“拆分任务”入口，跨页保留项目列表返回上下文。列表显示稳定任务编号、状态、负责人、估算/截止日和关联需求；可搜索标题、编号、说明，按状态、优先级、负责人、任务迭代或待分配筛选，需求过滤可从关联入口带入。筛选、分页及详情写入 URL，刷新恢复；越界页可返回第一页。

新建和编辑用抽屉。关联需求、可分配成员和迭代支持搜索与分页继续加载；新建默认沿用需求迭代。任务关联在创建后固定，负责人通过独立分配/认领弹窗维护，必须说明原因。详情展示开始条件，只有满足条件且有权限时显示“开始任务”；开始后的需求状态显示实现中，不开放测试或完成按钮。

详情分为任务说明、任务历史、讨论与附件。历史显示操作者、时间、原因及可读的前后变化；需求链接可返回确认依据。任务附件沿用 SeaweedFS，不显示内部对象键或存储实现字段。操作失败保留输入，版本冲突要求刷新；编辑抽屉和详情使用不同组件 key，操作弹窗位于抽屉上层。

## M2 阶段完成

任务页提供列表/看板切换、阻塞与逾期筛选；看板按待开始、进行中、已取消分列，每列分页和完整计数。拖动只触发允许的领域命令，原因/确认弹窗在提交后等待服务端成功；失败保留原位置并明确提示。窄屏工具栏换行，看板在组件内部横向滚动，不扩大页面宽度，键盘/点击按钮可完成相同行为。

阻塞弹窗必须填写原因与协助人，可调整协助安排；恢复、取消、需求影响核对均需说明。详情展示阻塞、协助人和需求基线变化提示；核对具体新修订不会自动清除阻塞。取消仍可查看历史和原资料。

需求详情增加关联任务分页/统计、修订与影响、旧确认基线及前后快照。已确认/实现中需求通过“修订需求”发起新草稿，必须说明原因、影响及实际调整，再重新评审。

工作台默认聚合我的任务、待评审需求、协助和迭代跟进，可按类型、关键词、状态、阻塞、逾期筛选，URL 保留上下文。事项直达对应详情；改派、取消、评审结论及恢复后下一次查询反映当前责任。没有把历史通知当作待办完成状态。

## M3-03 测试准备

需求详情在页签前展示测试准备提示，统计全量草稿、待评审、可使用、需复查和废弃数量。新增“关联用例”页签，展示编号/标题、评审状态、复查标记、负责人和评审人，支持独立分页及进入用例库/详情。失效的 READY 显示“待重新评审”，避免把最近评审状态当成当前可用资格。提示明确要求测试前核对验收标准，不用已有用例数量冒充覆盖率。

工作台类型筛选新增“待评审用例”和“需求变化复查”，直接进入对应详情。类型、搜索与分页继续写入 URL；处理完成后刷新当前待办。沿用需求详情抽屉、响应式换行和空态/错误重试。

## 当前任务与测试界面

现行规则见 ADR-008。任务列表筛选与看板只显示待开始、进行中、完成，开发在详情或看板执行开始、完成、重新开始和退回待开始。需求的待测试、测试中、已完成由后台汇总，不提供任意跳转。

项目提供测试记录页，替代提测管理和测试执行。支持按需求和结果筛选、分页和可刷新详情。用例详情可直接添加记录和查看多次测试；用例列表展示最近有效结果。复测与结果分别展示，如待复测、复测通过、复测未通过。

记录详情展示当时的用例内容、实际表现、环境、可选构建和关联缺陷，支持上传截图及文件。已完成结果只读，失效记录明确标记。手工缺陷的用例和记录关联可留空；缺陷详情可查看关联证据并发起复测。版本详情继续登记构建。

测试记录、缺陷、用例及需求之间提供跳转，权限来自服务端 allowedActions。空态、错误、保存反馈、桌面及 390px 窄屏验证见 [轻量测试验证](verification/lightweight-testing.md)。
