# ADR-009：简化版本交付

日期：2026-10-29；状态：已实施。

## 决定

在 ADR-008 的任务与测试记录模型上，以版本为中心记录人工发布。需求“已完成”仍表示开发与测试完成，不增加单独的业务验收申请或审批门禁。项目/迭代的既有关停能力继续沿用，复杂风险审批、复盘和结转不纳入本阶段。

## 发布和验证

- 版本详情显示未发布或已发布，登记发布时选择该版本的构建、实际时间、成功/失败及可选说明。失败记录不改变已发布状态，可重新登记。
- 服务端在项目写锁内重新检查：所选构建属于版本且范围版本一致；版本至少关联一个需求，所有关联需求当前状态为已完成；关联需求没有未解决的严重或致命缺陷，重复缺陷按主缺陷判断。前端展示具体原因和跳转入口。
- 成功发布设置版本为已发布并解除范围的活动归属，允许后续版本关联同一需求。发布记录保存检查快照（范围版本、需求状态与修订/测试轮次、构建及检查结果）。失败与成功记录均不可覆盖。
- 已发布版本可以登记上线验证通过或失败，也可以登记回滚时间和可选说明。验证与回滚关联对应的成功发布记录并追加历史；回滚后版本显示未发布，可再次登记发布。
- 管理员、项目负责人及有发布管理权限的成员可以登记，其他项目成员只可查看；版本并发校验、幂等及审计与记录同事务执行。
- 本阶段记录实际发生的人工部署，不执行部署或回滚。检查确认需求的当前测试状态及构建范围，**不证明所选构建本身已被测试**；发布负责人须核实实际部署包及其测试依据。

## 不在范围

独立业务验收、一般缺陷延期审批、自动部署、专门的生产验证清单、扩展复盘/结转和跨项目统计均不在本次简化范围；真实试运行、容量、生产部署和恢复演练属于后续 M6。
