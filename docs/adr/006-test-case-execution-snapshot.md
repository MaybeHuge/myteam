# ADR-006：正式执行用例快照 v1

日期：2026-10-28。状态：M3-04 契约与冻结服务、M4 批次持久化和不可覆盖结果均已实现。

## 背景与选择

现有 TestCaseRevision.snapshot 允许保存不完整草稿，用于用例修订历史。正式执行需要保存完整步骤/预期、责任和来源，并能在后续修订、需求变更或废弃后读取原文。

保留现有历史结构，新增独立的 `testCaseExecutionSnapshotSchema` 及只读类型 `TestCaseExecutionSnapshot`，版本为 `schemaVersion: 1`。不把草稿 schema 收紧，不为尚未实现的测试批次添加临时表或公开冻结接口。

## 快照内容

- projectId 及来源 testCaseId、revisionId、revision。
- 原修订的编号、标题、前置条件、有序步骤/预期、优先级和负责人身份快照。
- 全部关联需求的编号/标题和 requirementId/revision/scopeVersion 依据。
- 实际通过记录 reviewId、round、指定评审人、实际决定人及通过时间，保留管理员代评来源。
- capturedAt、capturedBy；时间为 UTC，冻结时间使用与评审记录一致的数据库时钟。

负责人、步骤和预期、需求范围和通过信息均必填；需求不能重复。步骤最多 100 个、需求最多 50 个，与现有编写边界一致。前置条件允许空文本。文本原样复制，尤其保留步骤中的换行及首尾空白。

## 生成、存储与读取

`TestCasesService.freezeExecutionSnapshot(tx, projectId, id, revision, capturedBy)` 在调用方事务中复用 selectUsableRevision 和 ADR-005 项目锁，检查当前可使用修订及全部需求依据，再核对当前评审轮次的真实 APPROVED 记录和修订/关联范围一致性。数据缺项或不一致返回 422，跨项目对象返回 404。

调用方须先完成当前用户的身份、test:execute、项目可写状态和批次范围授权，capturedBy 取自已认证会话。M4 在同一事务内将返回对象完整复制进执行项 JSON，并关联明确构建/环境及批次。工厂不独立提交事务；整个操作继续由调用方的幂等、审计与回滚机制覆盖。执行结果和证据由 M4 的结果记录追加保存。

schema 对每一层对象/数组执行运行时冻结，类型同样只读；Zod 解析产生独立副本，避免与源对象共享引用。JSON/JSONB 序列化保存值，重新读取时须再次通过版本化 schema 校验。M4 还须为执行项快照提供数据库不可覆盖约束；当前的 Object.freeze 不代替数据库约束。

历史读取保持原文；据此判断新的测试、验收或发布资格时，仍须校验当前需求依据、构建和对应结果。后续需求变更不会修改历史快照。

## 版本及兼容

每层对象严格校验未知字段；缺少版本、未知版本、空白步骤/预期、重复依据、非法来源或冻结早于通过时间均被拒绝。v1 不带草稿默认值或文本 trim 变换。

现有 TestCaseRevision.snapshot 和浏览器修订详情保持兼容，旧草稿继续可读。旧修订 JSON 不会被自动当作正式执行快照；工厂仅在资格通过后显式生成 v1。未来结构变化新增版本和对应读取分支，保留既有读取能力，不静默丢弃字段或把未知版本按 v1 解释。

本批无数据库结构迁移、配置或依赖变更。验证见 [M3 完成与快照验证](../verification/m3-completion.md)。

## M4 接入结果（2026-10-28）

M4 已在选择用例的授权事务内将完整 v1 快照持久化到 TestRunItem，保存实际构建及提交上下文。数据库拒绝覆盖或删除历史执行项、结果和处置；来源修订具备同项目复合外键。新批次使用当前可使用修订，旧批次从自身 JSON 读取内容，源用例修订不改变旧内容和结果。验证见 [M4 完成记录](../verification/m4-completion.md)。
