# ADR-007：版本、提测、测试批次与缺陷闭环

日期：2026-10-28。关联任务：M4-01—06。状态：实现完成，最终检查见 [M4 验证](../verification/m4-completion.md)。

本决策的提测、测试批次和任务测试状态已由 [ADR-008](008-lightweight-testing-records.md) 替代；本文保留原阶段设计背景。

## 版本和构建

Release 是提测和后续发布共用的目标版本，ReleaseItem 关联需求/任务，每次范围修订保留一组 scopeVersion。任务的父需求自动纳入范围；同一事项只属于一个尚未交付的活动版本。Build 保存唯一项目内构建标识、范围代次、代码/产物链接和登记说明，只追加，不提供覆盖接口。首期为实际构建的人工登记。

版本范围调整递增 scopeVersion，旧构建不能提交新范围，已待验收事项回开发重新验证；活动提测期间禁止调整范围。登记额外构建保留原构建及证据。READY/RELEASED/ARCHIVED 的版本交付操作由 M5 接入，M4 不提供发布命令。

## 提测和活动互斥

Submission 保存标题、版本、构建、接收人、任务、环境、自测和变更说明。DRAFT/RETURNED 可编辑，由创建人或项目负责人维护。提交时校验本人任务（负责人可代理）、已开始且未阻塞、进行中的迭代、当前确认需求依据、版本范围及构建代次；任务进入 READY_FOR_TEST。

SubmissionTask.active 的项目/任务部分唯一索引与项目事务锁共同保证 BR-20。退回释放活动范围、任务回 IN_PROGRESS；重提增加 round，每轮 SubmissionReview 完整保存交接快照及结论。只有指定接收测试人或项目负责人可接收，且每个需求已有可使用用例。接收后建立 PENDING TestRun，任务进入 TESTING。已接收内容和任务关联由数据库限制改写；构建改变必须新建提测单，完成的旧构建不能再次覆盖同一任务的新轮提测。

## 冻结和执行

批次先选择当前可使用修订，每个范围需求至少一条必要项。调用 ADR-006 的事务冻结服务，将完整 v1 JSON 实际保存进 TestRunItem；用例须只关联该次提测范围内需求。选择后调整需取消批次并保留原记录，另建提测。

批次和执行项引用明确构建/提测，快照与结果有同项目外键、来源校验及不可覆盖/删除保护。每次 TestResult 追加 attempt、实际表现、结论、原因、证据、批次附件引用和操作者。失败需要原因或缺陷关联；数据库的延迟约束在提交时检查关联已同事务建立。阻塞和不适用需要原因，不适用由项目负责人或系统管理员明确确认。

必要项未执行不能完成批次；最新结果含失败/阻塞或仍有相关阻断缺陷时，完成结论为未通过，任务回开发。条件通过时任务进入 ACCEPTING，需求下全部未取消任务具备条件后，需求才进入待验收。NOT_APPLICABLE 独立计数，不计为 PASSED。批次完成不等于业务验收或发布成功。

需求修订期间仍可查看旧快照和全部结果；记录新结果/完成须校验 ADR-005 需求依据，失效批次可取消。源用例后续修订保留冻结的执行内容。

## 缺陷、修复与复测

缺陷保留复现、预期/实际、严重程度、环境、发现构建/版本、需求/可选任务、开发和复测责任人。可从失败项创建或关联已有缺陷。生产来源必须引用实际已发布版本，并指定未交付的修复目标版本；实际生产发布和补丁流程继续由 M5 接入。

测试角色确认后 OPEN，指定开发开始 FIXING，提交说明、证据和实际修复构建后 AWAITING_RETEST。修复不能复用发现或已尝试的修复构建。指定复测人或负责人使用修复提交后、对应场景和实际修复构建上的最新执行结果给出结论：通过 CLOSED，失败 OPEN。开发权限不授予复测权限。DefectDisposition 和 DefectTestLink 只追加，修复、失败、再次修复和重开均可追溯。

重复结论需要同项目主缺陷，拒绝循环；阻断按主缺陷的未解决状态判断，兼顾原报告的严重程度。非缺陷、无法复现需测试权限、原因和证据，均可授权重开。只有一般/轻微问题可登记延期目标或日期，仍标为未修复，M5 再记录正式发布风险批准。严重/致命问题不能借延期绕过条件。

## 事务、权限和当前责任

所有写操作校验当前会话/Origin/CSRF、进行中的项目、角色、对象责任、版本和幂等键；项目行锁覆盖状态、范围、快照、结果、审计及站内通知。重放先执行当前授权。测试执行可由项目负责人改派，缺陷可改派开发/复测人和目标版本；成员移出、停用或失去相关权限前须处理未结束责任。

工作台从当前 Submission/TestRun/Defect 状态聚合接收、执行、待确认、修复、复测和延期跟进；完成、退回、改派和失权后更新，旧通知不充当当前待办。任务看板补全待测试/测试中/待验收等列，仍不允许用拖动代替测试和验收命令。评论及 SeaweedFS 私有附件扩展 RELEASE/SUBMISSION/TEST_RUN/DEFECT 授权目标。

M4 跨对象复合外键、部分唯一索引和历史保护由增量 SQL 迁移维护，Prisma schema 声明查询映射。业务升级只应用增量迁移，不重建业务库或填充演示记录。
