# ADR-011：需求在线图文文档

日期：2026-10-29。状态：已实施。

## 入口与编辑

需求详情的「需求文档」页签打开独立文档页，每个需求有一份文档。可创建空白文档，或从现有需求描述、验收标准生成模板。原有摘要和验收标准继续用于需求列表及完整性校验。

使用 Tiptap 编辑结构化 JSON，支持标题、粗体、斜体、字号、文字颜色、列表、HTTP/HTTPS 链接、表格、撤销与重做。字号支持 8–96px，可独立恢复默认字号和默认颜色；编辑、保存、固定版本及只读展示保持相同样式。图片可选择、粘贴或拖入，支持说明、宽度和阅读时放大；上传失败可重试或移除。「已上传图片」支持重新插入本需求已有图片，包含上传成功但未保留在正文的图片。界面支持中文/英语，用户正文保持原文。本期没有实时多人协同、Word 导入导出和外链图片抓取。

## 工作草稿与需求基线

自动保存仅更新独立工作草稿，不增加需求修订，不使测试依据失效。保存使用递增版本、项目锁和幂等键；冲突时保留本地输入，用户核对后显式加载最新草稿。上传中的临时节点不进入持久化正文；存在未完成上传时不能应用。未保存或上传中的内容离开页面前会提醒。

「应用到需求」在单个事务中生成固定文档版本并更新需求：草稿需求沿用原更新流程；已确认需求要求填写修订原因和影响范围，并沿用原修订流程，重新评审、标记用例待复核、重开已完成任务及使旧测试依据失效。任何中途失败都回滚。需求送审时禁止存在未应用的有效正文；无文档、空白草稿仍允许送审。

每次评审快照与修订前后快照保存文档版本 ID 和序号，历史页链接到相应固定正文。已有快照没有文档字段时继续兼容。固定版本不得修改或单独删除。当前需求搜索包含已应用文档的纯文本，不搜索未应用草稿。

需求元数据修订后，旧草稿基线不可直接应用。用户保留必要内容后显式重置为当前版本，再重新编辑。「放弃未应用修改」恢复当前文档或空白，同时增加草稿版本，避免旧客户端覆盖新草稿。

## 权限与图片生命周期

读取要求项目访问权限；草稿和未应用图片仅对具有需求编写权限且当前可编辑的成员开放。评审中、已取消需求、已关闭迭代，以及验收中/已完成/归档项目禁止修改。固定文档及其图片供项目授权读者查看。

图片由服务端校验内容与扩展名，仅允许 PNG/JPEG/WebP，单张不超过 20 MiB。正文只存绑定当前项目、需求的图片 ID，不存外链、Base64 或临时签名地址。每次展示通过会话授权流读取私有 SeaweedFS/S3 对象，返回正确类型、nosniff 和受限 CSP。上传重试不重复保留存储对象。

文档 JSON 按白名单校验节点、属性、链接和嵌套结构，限制深度、节点数、图片数及正文大小；阅读界面使用 React 节点渲染，不执行存储 HTML。

草稿保存更新图片引用，应用时建立固定版本与图片的引用关系。删除正文图片不立即删除对象，历史图片继续保留。现有 `storage:prune` 仅释放当前桶/前缀中超过 24 小时且没有任何草稿或固定版本引用的图片元数据，再清理未引用对象；项目锁防止与保存交叉删除。数据库复合外键阻止跨项目/需求关联，触发器保护固定版本和图片存储元数据。

## 数据库及接口

部署先执行 `./scripts/pnpm.sh db:generate` 和 `./scripts/pnpm.sh db:migrate`，新增迁移 `202610290015_requirement_documents`。迁移仅添加表和可空关联，不重写既有需求或评审数据。沿用已有私有资源桶配置。

基础路径：`/api/v1/projects/:projectId/requirements/:requirementId/document`。

| 方法与后缀                     | 用途                                     |
| ------------------------------ | ---------------------------------------- |
| GET `/`，可选 `versionId`      | 当前文档/指定固定版本、可见草稿及权限    |
| POST `/`                       | 创建空白/需求模板草稿                    |
| POST `/save`                   | 按草稿版本保存                           |
| POST `/reset`                  | 显式重置草稿                             |
| POST `/apply`                  | 按草稿版本及需求版本原子应用             |
| GET `/versions`                | 固定版本分页                             |
| GET `/images`                  | 需求编写者分页浏览和找回本需求已上传图片 |
| POST `/images?filename=...`    | 二进制上传                               |
| GET `/images/:imageId/preview` | 授权图片流                               |

写请求均要求会话、Origin、CSRF 和 Idempotency-Key，接口定义同步到 OpenAPI。

验证入口：`packages/contracts/test/documents.test.ts`、`apps/api/test/requirement-documents.integration.mjs`、`tests/e2e/requirement-documents.spec.ts`。集成使用隔离 PostgreSQL 与真实 S3，覆盖角色与项目隔离、幂等和并发、基线保护、修订失效、事务回滚、数据库不可变约束及图片清理；浏览器覆盖编辑/保存/图片重试/刷新/历史/冲突/语言与窄屏。

实际验证：格式、lint、类型检查及生产构建通过；40 项单元/契约测试、178 项真实 PostgreSQL/SeaweedFS 集成测试通过。全量 23 项浏览器场景首轮 21 项通过；定位并修复需求详情页签聚焦时的原生滚动冲突后，需求图文文档、草稿冲突、需求修订及评审相关 5 项复验全部通过。另验证语言切换与打开既有草稿不会因 JSON 属性顺序差异触发无效保存。本地业务库及隔离测试库均已应用新增迁移。

同一需求图片复制、拖动时仅解析匹配当前项目/需求授权地址的图片节点，禁止导入外链、Base64 和其他需求图片。上传完成以不进入撤销历史的节点转换替换临时预览，撤销/重做恢复最终图片，不恢复已释放的 blob。文字样式仅持久化受限的字号与颜色属性，不保存任意 CSS。

2026-10-30 补充验证：51 项单元/契约测试、12 项文档真实数据库/存储集成测试和 4 项文档浏览器场景通过；阅读页图片复制回编辑器的扩展场景另行复验通过。覆盖字号/颜色保存与独立恢复、图片撤销/重做、编辑与阅读页复制、图片库找回、刷新展示及权限隔离。本次样式与图片修复无需新增数据库迁移。
