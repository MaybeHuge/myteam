# ADR-001：技术栈与首期架构

- 日期：2026-10-27
- 状态：后端、数据与部署决策继续有效；前端及组件测试选型已由 [ADR-002](002-react-frontend.md) 替代；兼容性及运行能力待 M0-02/M6 验证
- 关联任务：M0-01
- 详细设计：[技术选型与架构设计](../architecture.md)

## 背景

MyTeam 面向单组织多项目协作，存在需求、任务、用例、提测、缺陷、验收与发布之间的紧密关系。首期需要项目权限隔离、状态流转、事务、并发控制和完整历史，目录尚无应用代码或既有技术约束。

默认按小团队、内部浏览器应用、单机先行规划。维护团队技术偏好、实际部署主机和容量尚未由用户提供；本 ADR 为可调整的实施决策，不是采购或上线批准。

## 决策

以下保留初始决策快照；当前前端采用 React，以 ADR-002 和最新架构文档为准。

1. 前端使用 Vue 3 + TypeScript + Vite + Element Plus，Vue Router 管理路由，Pinia 管理界面状态，TanStack Vue Query 管理服务端数据。
2. 后端使用 NestJS 12 + Express 适配器，ESM，TypeScript 6 作为版本目标。按业务领域构建模块化单体，通过显式应用服务协调事务。
3. 数据库使用 PostgreSQL 18，Prisma ORM 7 管理数据访问和迁移；数据库特有约束使用版本化 SQL。
4. 同仓库使用 pnpm workspace，包含 web、api 和独立 contracts 包；Zod 定义协议结构及校验。
5. 认证使用服务端数据库会话与 HttpOnly Cookie，项目 RBAC 叠加对象和状态策略；账号、角色变更即时校验。
6. 首期附件保存至私有持久卷，通过授权 API 下载，Storage 接口保留对象存储替换点。
7. 首期按 Linux + Docker Compose + Nginx 部署；单后端实例，数据库和附件持久化。TLS、域名及备份位置按实际环境补充。
8. 测试选用 Vitest、Vue Test Utils、Supertest 和 Playwright，接口层使用真实 PostgreSQL。
9. Node 使用 24 LTS，具体依赖和镜像补丁在初始化时固定；每次更新验证版本兼容。

## 备选与取舍

| 选项                       | 本次处理     | 原因及重评估条件                                                |
| -------------------------- | ------------ | --------------------------------------------------------------- |
| React 前端                 | 保留替代     | 当前无 React 资产约束，选 Vue 管理界面；团队偏好明确后可改      |
| Java/Spring 或 Python 后端 | 保留替代     | 当前按全栈 TypeScript 减少语言与契约切换；实际维护技术优先      |
| SSR 全栈框架               | 暂不采用     | 当前主要是登录后协作；公开内容和搜索收录需求出现时另评估        |
| 微服务                     | 暂不采用     | 跨模块事务多，首期共享进程与数据库；出现独立组织/负载边界后评估 |
| Redis/消息队列             | 暂不部署     | 会话、站内通知和首期查询可由数据库满足；后台工作量增加时再加入  |
| 托管云平台                 | 不绑定供应商 | 未提供账号和预算；保持数据库、文件及部署适配边界                |

## 后果与约束

- 前后端共享协议类型，但数据库实体不直接暴露到浏览器。
- 模块共用数据库事务，代码必须坚持模块边界，避免退化为互相任意写表。
- 单机与本地文件存储存在容量和故障边界，备份恢复不能替代高可用。
- Nest 12/TS 6/Prisma 7/前端工具组合必须经过初始化验证；依赖发布状态不能代替项目实测。
- 首期设计目标为 100 活跃账号、30 并发虚拟用户，具体数据量、延迟及恢复目标见架构文档；这些不是已通过的容量指标。
- 生产资源、证书和备份位置仍待配置，不影响本次选型决策完成。
