# 需求基线

版本：0.2（任务与测试流程调整）  
建立日期：2026-10-27  
状态：用于后续开发的工作基线；技术方案与首批工程已落地，组织规模、生产资源及人员安排仍需补充。

现行任务/测试状态与完成条件以 [ADR-008](adr/008-lightweight-testing-records.md) 为准。需求完成表示开发测试完成；独立业务验收与发布是后续能力。

## 1. 产品目标

为中小型研发团队提供多项目协作能力，完成以下链路：

项目立项 → 需求规划 → 任务开发 → 测试与缺陷修复 → 业务验收 → 发布与上线验证 → 复盘归档。

产品的核心价值是可追溯：从需求能找到任务、测试、缺陷、验收和发布记录；从生产缺陷能反查受影响的交付版本。

默认假设：单组织内部使用、浏览器访问、允许同一成员兼任角色、多人协作。多租户计费、原生移动端、外部客户门户不在首期范围。具体团队人数及容量目标在 M0 确认。

## 2. 角色与权限

采用系统角色与项目角色组合，所有业务接口在服务端检查项目访问及操作权限。

| 角色            | 主要权限                                                   |
| --------------- | ---------------------------------------------------------- |
| 系统管理员      | 用户启停、系统配置、项目创建及管理；访问与越权操作需要留痕 |
| 项目负责人      | 管理项目成员和计划、分配工作、处理风险、归档项目           |
| 产品/需求负责人 | 维护和评审需求、确认范围、执行业务验收                     |
| 开发人员        | 维护授权任务、提交提测、确认并修复缺陷                     |
| 测试人员        | 编写和评审用例、创建测试记录、执行测试、提交和复测缺陷     |
| 发布负责人      | 检查发布条件、登记发布、回滚及上线验证                     |
| 只读成员        | 查看授权项目业务记录，不可修改                             |

约束：角色可兼任，但操作资格必须基于显式授权。首期不强制修复人与复测人是不同自然人，所有操作均记录实际操作者；严格职责分离列入后续配置能力。普通成员不能通过修改请求中的项目 ID、对象 ID 或负责人字段绕过权限。

## 3. 功能清单与阶段

优先级定义：P0 为首期闭环必需；P1 为流程深化；P2 为集成和规模化扩展。P0 不能按单一模块独立宣称完成，必须通过端到端验收。

| 编号  | 模块         | P0 首期                                                                   | 后续扩展                                 |
| ----- | ------------ | ------------------------------------------------------------------------- | ---------------------------------------- |
| FR-01 | 账号与权限   | 登录、退出、用户启停、项目角色、权限校验                                  | 单点登录、自定义角色                     |
| FR-02 | 项目与成员   | 项目增改查、成员管理、状态、只读归档                                      | 项目模板、组织结构                       |
| FR-03 | 迭代与计划   | 基础迭代、负责人、起止日期、关联需求、结转                                | 容量规划、里程碑、跨迭代统计             |
| FR-04 | 需求         | 描述、优先级、负责人、验收标准、评审、状态、关联追溯                      | 需求基线、变更影响分析                   |
| FR-05 | 任务         | 拆解、指派、看板、截止日、估算、阻塞标记、状态                            | 子任务、依赖、工时、批量操作             |
| FR-06 | 用例         | 用例库、需求关联、步骤/预期、草稿/评审/可用/废弃                          | 目录、标签、批量导入、版本对比、覆盖分析 |
| FR-07 | 测试记录     | 从用例发起、需求隔离、环境/可选构建、用例快照、结果及截图、失败自动建缺陷 | 多轮计划、环境管理、报告模板             |
| FR-08 | 缺陷         | 严重程度、复现、负责人、发现/修复构建、复测、重新打开、延期               | 重复聚合、服务等级、跨版本分析           |
| FR-09 | 业务验收     | 按标准验收、通过/不通过、问题回流、验收记录                               | 多级会签、验收模板                       |
| FR-10 | 发布         | 版本范围、发布检查、发布记录、失败/回滚、上线验证、风险例外               | 自动部署、审批编排、灰度发布             |
| FR-11 | 工作台与协作 | 我的待办、列表筛选、评论、基础附件、站内通知、操作历史                    | 外部消息、全文检索、订阅                 |
| FR-12 | 复盘与统计   | 项目/迭代交付摘要、遗留事项、复盘记录、归档                               | 趋势报表、跨项目统计、导出               |

首期支持登记环境、代码和部署链接，发布操作在外部执行后由平台登记。平台首期不直接执行代码构建、自动化测试、部署和回滚。

## 4. 首期页面

1. 登录页、无权限页、账号停用提示。
2. 工作台：我的任务、待评审、待填写测试记录、待修复、待复测、待验收、逾期。
3. 项目列表、项目概览、成员与设置。
4. 基础迭代列表、详情与未完成事项结转。
5. 需求列表、编辑、详情、关联对象和评审。
6. 任务列表、看板、详情。
7. 用例列表、编辑、详情和评审。
8. 测试记录列表、详情、结果与截图附件。
9. 用例内发起测试和查看多次测试记录。
10. 缺陷列表、详情、修复和复测操作。
11. 需求验收页、验收历史。
12. 版本列表、范围配置、发布检查、发布及验证记录。
13. 项目/迭代复盘、遗留事项、历史动态。

## 5. 统一字段与交互

核心对象具有内部唯一 ID、可读业务编号、项目 ID、标题、状态、负责人、创建人、创建/更新时间及并发版本号。具体编号范围和生成方式在工程设计阶段确定，必须满足并发唯一。

- 列表分页，按项目、状态、负责人、优先级、迭代、版本等适用字段筛选。
- 详情展示关联记录、评论、附件及状态历史。
- 优先级与严重程度分开：需求/任务使用优先级；缺陷同时记录业务处理优先级和影响严重程度。
- 逾期和阻塞为独立标记，不代替业务状态。阻塞需要原因和协助人。
- 首期不提供核心记录物理删除；未使用草稿可取消，已参与流程的记录保留历史。
- 关联对象必须属于同一项目；跨项目迁移不在首期范围。
- 重要操作失败时保留表单输入，错误信息指出具体原因。

## 6. 非功能要求

| 方面     | 首期要求                                                            |
| -------- | ------------------------------------------------------------------- |
| 权限     | 所有业务请求执行服务端授权；附件下载也需要授权                      |
| 一致性   | 状态流转、日志和关键关联按事务提交；重复提交不能产生重复验收或发布  |
| 并发     | 修改携带版本号或等价机制；冲突时提示刷新，不能静默覆盖              |
| 安全     | 凭据不明文保存；会话可失效；限制上传大小/类型；敏感数据不写业务日志 |
| 可追溯   | 状态变化记录前后值、操作者、时间、原因；历史测试快照不被覆盖        |
| 可恢复   | 具备数据库迁移、备份与恢复步骤，上线前验证恢复可用                  |
| 可运维   | 配置与代码分离，具备健康检查、错误日志、部署和回退说明              |
| 可访问性 | 基础键盘操作、表单标签、可读错误提示；不能只靠颜色表达状态          |
| 性能     | M0 明确目标并发、数据量及响应指标，未确认前不宣称支持规模           |

## 7. 首期交付定义

必须同时满足：

- 核心角色可以完成真实操作，业务数据持久化且权限隔离生效。
- 用例在需求确认后建立，与开发并行，提测前完成准备。
- 每次测试保存当时用例快照，修复后可对新构建复测与回归。
- 阻断问题能阻止验收或发布，风险例外有授权和记录。
- 版本发布结果、上线验证、失败处置可追溯。
- 项目归档前处理遗留事项，归档后业务记录只读。
- docs/acceptance.md 的 P0 必测项有实际验证证据。
