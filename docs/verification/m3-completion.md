# M3-04 快照数据契约与 M3 阶段退出验证

执行日期：2026-10-28。范围：M3-04 及 M3 阶段退出；前序证据见 [用例库与评审](m3-cases.md)、[测试准备](m3-preparation.md)。

## 交付范围

- 新增独立 v1 正式执行快照契约：来源项目/用例/具体修订、完整内容、需求依据、真实评审和捕获来源；原草稿修订历史保持兼容。
- 新增服务内部 `freezeExecutionSnapshot`，在调用方事务内复用项目行锁、当前可用修订和 ADR-005 需求校验，检查当前 APPROVED 轮次及历史内容/关联范围一致性。冻结时间来自数据库时钟，步骤按原始 JSON 复制。
- schema 严格拒绝未知/缺失版本、未知字段、不完整步骤或负责人、重复需求、非法来源元数据和时间倒置；解析时复制并逐层冻结，JSON 再读取时可独立解析。
- OpenAPI components 中提供同一 schema，HTTP 业务路径保持现状。无新增依赖、配置、数据库表或迁移。
- 详细边界及 M4 接入职责见 [ADR-006](../adr/006-test-case-execution-snapshot.md)。

## 快照验证证据

1. 版本、各层严格字段、完整内容/步骤上限、重复/空需求范围、元数据及时间顺序均有契约检查；旧草稿历史继续允许 owner=null 和 steps=[]，不能被误读为正式执行快照。
2. 对象、内容、步骤数组及项、责任身份、需求数组及项、来源和评审记录均冻结；改变原输入不影响解析结果。JSON 往返和真实 PostgreSQL JSONB 往返均完整保留文本与顺序，重新解析仍逐层只读。
3. 服务输出引用实际修订 ID、当前评审轮次 APPROVED 的记录 ID、指定评审人及实际决定人；管理员代评同时保留两种身份。快照包括所有关联需求的真实 revision/scopeVersion。
4. 后续需求修订/确认、用例建立新内容修订、改派、重新通过及废弃后，已捕获的旧快照编码保持不变，并可单独读取；旧来源不得重新冻结。
5. 草稿、待评审、废弃、跨项目、没有真实通过记录的伪 READY 及缺失来源修订被明确拒绝。事务内暂存损坏历史样本验证缺失步骤/预期/负责人、错修订、错需求与重复依据均被拒绝，样本最终回滚；原文包含空白/换行的合法样本无 trim 变化。
6. 冻结与需求修订并发后，旧需求依据不能再次冻结；若冻结先获得项目锁，则其副本保留原基线，后续需求修订只影响新的选择资格。

## M3 阶段退出

手机号登录作为协作平台的样例业务需求，建立正常验证码、错误验证码、过期验证码和重复使用验证码四条独立用例。重复使用场景退回，补充“第二次请求不建立新会话”，修改后重新送审通过，保留两次内容修订与四条评审历史。

集成检查同时拆分两项开发任务：第一项在四条用例仍为草稿时开始；测试评审独立进行；四条通过并分别产生完整执行快照后，第二项任务仍可独立开始，两项最终均保持 IN_PROGRESS。需求下用例明细、四条可使用统计与完整来源一致。

浏览器完成四类用例、重复使用场景退回/修改/重审、需求下四条可使用用例及两项关联任务检查；两项任务在测试准备前后均可独立开始。控制台无运行错误，390px 窄屏无整页横向溢出。已查看 `test-results/m3-exit-desktop.png` 与 `test-results/m3-exit-mobile.png`：桌面准备统计及关联列表可读，窄屏滚动到四类用例仍可完整查看状态和责任人。

## 验收与范围

M3-04 交付快照结构、校验和冻结服务。M4 将在自身身份、test:execute、项目/批次状态及范围授权后，同一事务内把完整 JSON 复制到实际执行项，并提供数据库不可覆盖约束、构建/环境关联和结果历史。本批未执行真实测试批次或查询历史测试结果，AC-13 只验证其快照契约部分；AC-12 的真实批次选择及 AC-10 的验收/发布继续由 M4/M5 验证。

运行时 Object.freeze 和类型只读保护对象副本，M4 的持久化不可覆盖约束仍需单独实施及验证。生产部署、容量与恢复保持 M6 范围。

检查日志保存在 `.local/m3-snapshot-check.log`、`.local/m3-snapshot-integration.log`、`.local/m3-snapshot-e2e.log` 和 `.local/m3-snapshot-cases-final.log`。本批构建仍有既有公共 UI 包体积提示，集成/浏览器仍有 pg 并行查询弃用提示，检查退出码均为 0。
