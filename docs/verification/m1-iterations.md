日期：2026-10-27。范围：基础迭代、计划归属基础与未完成事项关闭保护；完整结转仍属于 M5-06。

## 1. 已交付范围

- 项目详情新增「迭代计划」页签，提供真实统计、名称/目标搜索、状态与我负责筛选、分页、详情。
- 新建与编辑迭代名称、目标、负责人、必填起止日期。日期不能倒置，不能超出已设置的项目日期。
- 项目内名称唯一；负责人须为有效项目成员。尚有未关闭迭代时不能移出或停用负责人。
- `PLANNING → ACTIVE → CLOSED`；启动需要目标和进行中的项目，关闭需要总结且所有范围条目已处理。已关闭迭代不可编辑、重新启动或继续加入事项。
- 已完成、待验收和已归档项目的迭代只读。暂停项目可整理计划/关闭已完成迭代，不能启动新迭代。
- 写入执行当前权限、项目锁、版本校验和幂等；状态与审计在同一事务中提交，编辑审计保留计划前后值。
- URL 保留页签、筛选、分页与详情上下文；编辑/状态弹窗使用打开时版本快照。

## 2. 数据及后续模块接口

迁移：`apps/api/prisma/migrations/202610270003_iterations_plan/migration.sql`。新增 Iteration、WorkItem 及枚举，不修改原账号/项目记录，无需新配置。

WorkItem 是 M2 需求/任务的共同计划基础，持有稳定 ID、项目、可空迭代、类型、标题和处理结论（OPEN/DONE/CANCELED）。后续 Requirement/Task 以同一 ID 扩展领域详情与各自状态，不能另外复制当前迭代字段。当前没有公开 WorkItem 创建、取消、完成或删除接口，不能借此绕过未来业务流程。

项目/迭代使用复合外键，数据库拒绝跨项目计划关联。M2 写入前必须在同一事务完成领域授权，调用 IterationsService.assertAssignable 获得项目锁、验证同项目与未关闭状态，再保存 WorkItem 与领域详情及审计；完成/取消结论与领域状态同事务更新。关闭迭代使用同一项目锁并统计全部 OPEN 条目，包括分页之外的条目。

集成与浏览器中的范围条目是明确标注的隔离夹具，用于验证门禁，不代表需求/任务业务已经实现。业务库不填充示例迭代或范围条目。
