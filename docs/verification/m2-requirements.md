日期：2026-10-27。范围：需求草稿与确认基线、评审历史及现有计划/协作接入。

## 1. 已实现

- 项目内稳定编号，功能/维护类需求；草稿维护标题、描述、验收标准、优先级、负责人及迭代。列表支持组合筛选和分页，URL 保留筛选与详情，越界页可以恢复。
- 指定具备评审权限的本项目可用成员送审；只有指定评审人可确认/退回，管理员代审必须说明原因并留痕。草稿可不完整，送审和确认都需描述、负责人及验收标准。
- 退回、撤回、重新送审按轮次保留原始快照与意见；确认时核对本轮基线。需求和关联成员/迭代后续改名不覆盖历史。
- 草稿可附原因取消；评审中禁止直接编辑；已确认只读。并发写入校验 version，成功命令幂等重放前再次验证当前授权。
- Requirement 以同 ID 扩展 WorkItem，只维护一份标题/迭代；确认仍为 OPEN，取消同步 CANCELED，真实需求继续参加迭代关闭门禁。
- 新增 REQUIREMENT 协作目标，复用评论、SeaweedFS 私有附件、站内通知及授权下载。需求负责人移出/停用前须处理未结束需求；待评审人失权、移出或停用前须完成或撤回待评审事项。

## 2. 检查范围

新增 2 项契约检查：不完整草稿与字段默认值、标题/验收标准边界、禁止输入跳状态、版本和评审人必填、退回/撤回/取消必须说明原因、非法筛选与需求协作目标。

新增 13 项真实 PostgreSQL / SeaweedFS 集成检查：

1. 两个项目与管理员/负责人/产品/开发/测试/只读/非成员隔离，指定评审人及管理员代审边界。
2. 不完整草稿、命令幂等、编号及同 ID WorkItem。
3. 不可用/跨项目/无权限负责人和评审人、关闭/跨项目迭代、候选分页及搜索。
4. 编号/描述搜索，状态、负责人、优先级、类型和迭代组合筛选及分页。
5. 退回、修改、重新送审和确认，多轮快照不覆盖，成员/迭代改名后确认仍有效，历史分页及数据库禁止更新旧记录。
6. 确认时再次检查完整性与基线，失败无部分写入，退回允许恢复流程。
7. 同版本并发编辑及确认/退回竞争，只有一次状态、历史和通知变更。
8. 待评审人移出/停用/收回权限保护，撤回及重新分配；需求负责人移出/停用和移交保护。
9. 不能清空迭代逃避关闭门禁；跨迭代需原因；取消后可以结束本轮。
10. 事件故障时业务数据、编号、通知、审计、历史及幂等同事务回滚。
11. 失权后拒绝旧成功命令重放，待验收项目只读。
12. 数据库拒绝跨项目需求、错误 WorkItem 类型和后续类型篡改。
13. 需求评论、真实 SeaweedFS 上传下载、只读及跨项目/非成员下载边界、取消后协作只读。

新增 1 项跨角色浏览器流程：不完整草稿送审失败、补齐内容、产品退回、修改及重新送审、产品确认、旧快照和意见、只读访问、需求讨论入口、筛选刷新、桌面与窄屏。包含运行时及非预期控制台错误检查。修复详情抽屉和编辑抽屉的重复组件 key、评审弹窗层级及按钮无障碍名称；原有窄屏断言等待布局稳定。
