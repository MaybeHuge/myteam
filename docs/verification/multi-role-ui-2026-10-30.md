# 多项目、多角色界面回归（2026-10-30）

## 执行范围

使用 Playwright 无头 Chromium 操作真实 React / Nest / PostgreSQL 应用。新增场景中的账号、项目、成员、需求、任务、用例、测试记录、版本和构建均从界面创建；GET 请求仅用于核对持久化结果，额外的写请求仅用于验证只读账号被返回 403。

新增场景使用隔离数据库 `myteam_roles_test`，原有回归使用 `myteam_test`。附件相关回归连接真实 SeaweedFS 私有测试桶。测试数据保留，业务数据库不参与本轮测试。

## 新增流程

每个项目配置普通负责人、产品、两名开发、测试、发布及只读成员，管理员移交主负责人后，由普通角色推进流程。

每个项目通过界面建立 3 个需求、每个需求拆分 2 个任务：

1. 需求一由产品送审、负责人确认，两名开发分别开始并完成自己的任务；测试人员创建用例，负责人通过用例评审，再由测试人员登记通过结果，核对需求完成。
2. 需求二已确认，一项任务进行中，另一项任务待开始，用于对比本人、其他开发及其他角色的操作入口。
3. 需求三保留在评审中，验证非指定评审人没有确认入口、未确认需求下的任务不能开始。

第三个项目交换同一组账号的产品、只读角色，检查项目权限是否隔离。发布人员另外从界面创建版本并登记构建，测试人员验证该构建后，由发布人员登记发布及上线验证。

## 原有回归与测试修正

原有场景覆盖登录与账号、项目与成员、迭代关闭、评论与附件、需求退回重审、任务认领及改派、看板阻塞恢复、需求修订、用例复审、测试失败建缺陷、修复复测、发布失败重试、上线验证、回滚，以及文档图片、中文英语和窄屏。

首次执行原有 25 个场景有 22 个通过。需求和任务场景假设固定项目在列表首页；随着测试数据增加，该项目已进入后续分页。现改为在界面搜索项目标识 `VTEAM` 后打开，任务复跑通过。工作台一次刷新超时，单独复跑通过。资源竞争下的需求场景另行顺序复跑，最终结果在下节记录。

新增场景使用独立 Cookie 上下文切换账号，并卸载非活动页面，降低多个 React 工作区同时运行的资源开销。套件总超时调整为 20 分钟，以容纳新增的完整多项目场景；仍为单 worker、无自动失败重试。

本轮创建流程已完成后，权限检查发现测试定位遗漏按钮图标的可访问名称。截图确认按钮实际存在，调整为兼容图标前缀的名称匹配，并等待质量列表结束加载后检查隐藏按钮。保留界面创建的数据，以 `MYTEAM_UI_AUDIT_RESUME` 指定检查点继续检查；没有通过接口补建这些业务对象。

## 最终结果与证据

新增场景分阶段完成：先通过界面完成对象创建，保留数据后修正定位并继续权限和发布检查，最终恢复执行为 **1 passed（3.6 分钟）**。

原有 25 个场景分批复核完成：首轮 22 个通过，任务和工作台各 1 个复跑通过，需求评审场景最后独立复跑为 **1 passed（33.6 秒）**。该场景覆盖不完整草稿、指定评审、退回修改、重提、评审快照、确认、只读访问、搜索后刷新和窄屏。另独立打开同一搜索地址，接口返回 200，结果约 1.5 秒显示。
